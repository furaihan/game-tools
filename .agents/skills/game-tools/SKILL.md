## Architecture Principles

### Feature-First Organization

Each tool is self-contained under `src/features/<tool-name>/`. Features import from `shared/`, never the reverse. Features can be shared across tools (e.g., `river-generator` is used by `biome-generator`) — in that case the shared feature has its own `core/`, `types/`, and `workers/` directories but no `components/` or `context/` of its own; consuming tools import directly from the shared feature's `core/` and `types/`.

Core logic (`features/<tool>/core/`) is pure TypeScript with zero React or UI dependencies.

### State Management: Tool-Scoped Context

Each tool manages its own state via React Context providers. There is no shared global context between tools.

- **Biome Layout Generator**: Single `BiomeGeneratorProvider` — state includes `biomes`, `seed`, `resolution`, `algorithm`, `biomeMap`, `isGenerating`, `isFiltered`, `error`, `generationStatus`. Actions: `setBiomes`, `setSeed`, `setResolution`, `setAlgorithm`, `loadPreset`, `randomizeSeed`, `generate`, `randomizeAndGenerate`, `applyMajorityFilter`, `exportPNG`, `copySeed`, `resetToDefaults`.
- **Sandbox Codec**: Advanced **4-context split** pattern for granular re-render control:
  - `SandboxActionsContext` — stable action callbacks
  - `SandboxValuesContext` — hot data (`values`, `disabledOptionIds`)
  - `SandboxUIContext` — UI state (`decodeInput`, `searchQuery`, `activeTab`, `currentCode`)
  - `SandboxDerivedContext` — computed data (`groupedOptions`, `filteredGroups`)
  
  Granular hooks: `useSandboxActions()`, `useSandboxValues()`, `useSandboxUI()`, `useSandboxDerived()`. Convenience hook `useSandboxCodec()` composes all four (for top-level layout only).

### Adding a New Tool

1. **Create the route**: `src/routes/<game>/<tool-name>/index.tsx`
   - Use `createFileRoute` with path `/<game>/<tool-name>/` (e.g. `/7dtd/biome-layout-generator/`)
   - The TanStack Router plugin auto-generates `routeTree.gen.ts` on dev/build

2. **Create feature module**: `src/features/<tool-name>/` with standard subdirectories:
   - `components/` — React UI components
   - `context/` — React Context for tool state (if needed)
   - `core/` — Pure business logic (no React)
   - `types/` — Type definitions

3. **Register in tool registry**: Add entry to `src/shared/tool-registry/tool-list.ts` with `title`, `description`, `href` (from routeTree types), `gameCategory`, and `icon` (lucide-react). Navigation appears automatically in both the sidebar nav and home page card grid.

4. **Use `@/` imports** — Vite resolves `@` → `./src`

### Route Path Convention

- 7DTD tools: `/7dtd/<tool-name>/`
- Other games in the future: `/<game>/<tool-name>/`

### File Naming Conventions

- React components: PascalCase (e.g., `CanvasPreview.tsx`)
- Context providers: PascalCase (e.g., `SandboxCodecContext.tsx`) or kebab-case suffixed `-context` (e.g., `biome-generator-context.tsx`)
- Hooks: kebab-case prefixed `use-` (e.g., `use-mobile.ts`)
- Core modules: kebab-case (e.g., `random-seeds.ts`)
- Workers: descriptive suffix `.worker.ts` (e.g., `biome-generator.worker.ts`)
- Route files: kebab-case (e.g., `biome-layout-generator/`)

### Coding Conventions

- **No JSDoc comments** unless explaining a complex algorithm.
- **No emojis in code** (user experience preference).
- **Import paths**: Use `@/` alias for project imports (e.g., `@/shared/ui/button`, `@/features/biome-generator/core/prng`).
- **Imports**: Prefer named exports. Group: React/external → context → hooks → core → local components.
- **Types**: Defined in feature `types/` or `shared/types/`. Import via `import type`.
- **State**: React Context for tool-level state. Core pipeline functions are pure — no React dependency.

### shadcn/ui Component Management

- Components stored in `src/shared/ui/`
- Config in `components.json` (style: `base-nova`, icon library: `lucide`, CSS-in-CSS with Tailwind v4)
- Add new components: `bun x shadcn@latest add <name> -y`
- After adding, files may be created in `@\components\ui\` (literal `@` dir) — move them to `src\shared\ui\` manually
- Current components installed (27): accordion, alert, badge, button, card, dialog, dropdown-menu, field, input, label, progress, scroll-area, select, separator, sheet, sidebar, skeleton, slider, sonner, switch, tabs, textarea, toggle, toggle-group, tooltip

### Web Worker Pattern

Workers are created via `new Worker(new URL('<relative-path>', import.meta.url), { type: 'module' })`.

The relative path must be from the calling file's location. For example, from within a context file in `features/biome-generator/context/`:
```ts
new Worker(new URL('../workers/biome-generator.worker.ts', import.meta.url), { type: 'module' })
```

Use `(self as any).postMessage()` for worker postMessage to avoid DOM type conflicts with `DedicatedWorkerGlobalScope`.

Workers communicate via typed messages:
- `{ type: 'progress', value: number }`
- `{ type: 'result', payload: T }`
- `{ type: 'error', message: string }`

Use transferable `ArrayBuffer` for large data (ImageData buffers, label arrays) to avoid copying.

### Theme System

Custom ThemeProvider at `src/app/theme/theme-context.tsx`:
- Uses `useState` + `localStorage` for persistence
- Toggles `.dark` class on `document.documentElement`
- Provides `isDark`, `toggle`, and `setTheme` via context
- Custom implementation — not using `next-themes` despite it being in dependencies

### Modal System

Reusable modal stack at `src/shared/modal/`:
- Context-based `ModalProvider` supporting `default`, `confirm`, and `alert` modes
- Configurable sizes: `sm`, `default`, `lg`, `xl`, `full`
- Uses `@base-ui/react/dialog` primitives
- Access via `useModal()` hook

### Tailwind v4 Notes

- CSS-first configuration via `@import "tailwindcss"` in `index.css` (also imports `tw-animate-css` and `shadcn/tailwind.css`)
- CSS variables defined with OKLCH values (shadcn theme)
- `@theme inline { ... }` maps CSS variables to Tailwind utility classes
- Dark mode via `@custom-variant dark` (class-based)
- No `tailwind.config.ts` file
- Animations via `tw-animate-css` (imported as `@import "tw-animate-css"`)
- Fonts: Inter (sans-serif), JetBrains Mono (monospace) via Google Fonts
- Utility classes: `bg-background`, `text-foreground`, `border-border`, etc.

## 7DTD Biome Layout Generator

### UI Layout
Three-column layout: GeneratorControls (left sidebar) | CanvasPreview (center) | BiomeList (right sidebar)

### Generation Modes
- **Simple mode**: Uses a single algorithm from the list below
- **Noise mode**: Uses procedural noise with configurable scale/octaves + biome mapping strategy

### 9 Simple Algorithms
| Algorithm | Description |
|---|---|
| Random Seeds | Place random seeds per biome, region-grow |
| Territory Expansion | Expand biome territories from seed points |
| Random Walkers | Agents walk randomly, claim territory |

| Cellular Growth | Cellular automaton growth |
| Probability Fields | Per-biome probability field sampling |
| Recursive Split | Recursive spatial partitioning |

- Perlin, Simplex, Fractal, Worley
- Configurable: scale, octaves, persistence, lacunarity
- Biome mapping: `"Threshold Bands"` or `"Multi-Layer Argmax"`

## 7DTD Sandbox Codec

Encodes and decodes 7 Days to Die V3.0 sandbox server preset codes — compact alphanumeric strings representing server configuration presets.

### Route
`/7dtd/sandbox-codec/`

### UI Layout
Single-page two-tab layout: **Decode Mode** (paste code → inspect/change parsed options) and **Encode / Edit All** (browse all 152 options → live code preview).

### How It Works
Sandbox codes use a simple encoding scheme:
- **Version prefix**: Single character `A` (current version)
- **Option entries**: 2-character option ID (`AA`–`ZZ`, 0–675) + 1-character value index (`A`–`Z`, 0–25)
- Only non-default values are encoded, keeping codes compact

### Features
- **Live code preview** — Encode tab: code updates in real-time as options change
- **Search/filter** — Filter 152 options by display name across 9 categories
- **Dependency system** — Some options enable/disable others based on value (e.g., XP multiplier at 0 disables Show XP)
- **Decode warnings** — Invalid entries, unknown option IDs, and out-of-range values are reported without crashing
- **URL sync** — `?code=` search param synced to the route for shareable links
- **Copy to clipboard** — One-click copy of the encoded code

### Core Module
**`src/features/sandbox-codec/core/sandbox-option-codec.ts`**: Full encode/decode implementation. Exports `encodePresetToCode(values)` and `decodeCodeToPreset(code)`, plus `CODEC_VERSION` and the alpha-index helpers (`indexToAlpha`, `alphaToIndex`, etc.). Option lookups and the disabled-option dependency cascade live in `sandbox-option-registry.ts` (`optionsByEnum`, `optionsByCategory`, `getDefinition`, `getValueSet`, `getDefaultIndex`, `createDefaultState`, `applyDisabledCascade`).

### Key Types (`src/features/sandbox-codec/core/`)
- `sandbox-option-definition.types.ts` — `SandboxOptionDefinition` (and int/float/bool variants), `SandboxOptionState`
- `sandbox-option-value-set.types.ts` — `SandboxOptionValueSet`, `SandboxValueType`, `getValueIndex`/`getDisplayAtIndex`
- `sandbox-option.enum.ts` — `SandboxOption` enum (option IDs)

### Components
- `SandboxCodec.tsx` — Main orchestrator (tabs, layout)
- `SearchBar.tsx` — Search input for filtering options
- `OptionRow.tsx` — Single option row with controls (React.memo)
- `OptionControl.tsx` — Dropdown/slider/toggle based on option type (React.memo)
- `LiveCodeCard.tsx` — Shows live generated code with copy button
- `EncodePanel.tsx` — All 152 options grouped by 9 categories (Edit All mode)
- `DecodePanel.tsx` — Decoded changed options + paste input (Decode mode)

### State Management
Uses a **4-context split** in `SandboxCodecContext.tsx` for granular re-render control. See State Management section above for details.

## 7DTD River Generator

Procedurally generates river networks for 7 Days to Die maps by midpoint-displacing a main-stem
centerline between two map edges, attaching midpoint-displaced tributaries, and stamping the
result as a binary water mask.

### Route
No standalone route — integrated as a sub-component within the Biome Layout Generator at `/7dtd/biome-layout-generator/`. Exposed via the `RiverControls` component in the GeneratorControls sidebar.

### How It Works
- **Main stem**: `midpointDisplace` draws a centerline between a source and target edge point (midpoint displacement with `DISPLACEMENT_DECAY=0.5` and `MAX_DISPLACEMENT_RATIO=0.3` to keep turns smooth), then `smoothPath` applies a box filter whose pass count scales with roughness.
- **Branches**: `selectBranchPoints` picks up to `branchCount` stem indices; each branch is a midpoint-displaced polyline from its stem point to the nearest dry edge cell. Bank side is chosen 50/50 per branch using the cross product of local flow vs. candidate offset (`findNearestValidEdgePoint`, `desiredSide`), so tributaries spread across both banks.
- **Stamping**: `stampRiver` paints tapered `stampCircle` disks along each polyline into a binary `Uint8Array` water mask (1 = water), with value-noise radius jitter. `ensureBranchConnects` re-anchors a branch origin only if its origin cell is unwet (tiny local blob only, never a long stroke). `smoothGrid` applies one cellular-automata cleanup pass.
- **Connectivity guarantee**: each branch's origin is its exact stem point, so tributaries always meet the main stem; no long reconnection lines are drawn.

### Core Modules (`src/features/river-generator/core/`)
- `index.ts` — Public exports: `generateRiversCore`, `buildRiverTrace`, `createValueNoise2D`, `stampCircle`, `strokeLineTapered`.
- `river-generator.ts` — Main pipeline: `generateRiversCore` (public API, returns a `WaterMap`) and `buildRiverTrace` (test/debug seam returning the centerline, smoothed stem, and per-branch polylines).
- `noise.ts` — `createValueNoise2D` for stamping radius jitter.
- `stamp.ts` — `stampCircle` (filled disk) and `strokeLineTapered` raster primitives.

### Key Types
- `WaterMap` (types): `{ width, height, seed, data: Uint8Array }` binary water mask
- `RiverGenParams` (types): `{ width, height, seed, branchCount, mainStemWidth, branchWidth, roughness }`
- `RiverGenStatus` (types): generation phase + progress
- `RiverTrace` / `RiverBranchTrace` (core): debug seam, with `origin`, `points`, `side`, `desiredSide`, `reconnectPixels` per branch

### Worker
- `river-generator.worker.ts` — Runs `generateRiversCore` in a Web Worker, posting `status` / `success` / `error` messages.

### Tests
- `__tests__/river-generator.test.ts` — Seed determinism, branch bank distribution, turn-angle cap under high roughness, and a zero-reconnect-scar regression.

### Integration
The River Generator is a shared feature module imported by the biome-layout-generator's `GeneratorControls` component, writing into a `WaterMap`.

## Future Games/Tools

This project is designed to host multiple games and tools. Add new games as top-level route segments:
- Route: `/7dtd/<tool-name>/` for 7 Days to Die tools
- Route: `/<game>/<tool-name>/` for other games
- Register in `src/shared/tool-registry/tool-list.ts` — navigation appears automatically in sidebar nav and home page
- Each new tool creates its own state management — no global context shared across tools
- Features can be shared across tools (e.g., `river-generator` shared with `biome-generator`) — place shared capability under `src/features/<game>/` and import from the consuming tool's feature module
